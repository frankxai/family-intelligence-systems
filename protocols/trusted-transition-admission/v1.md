## Purpose

JSON Schema validates document shape; it cannot prove that a receipt exists in a trusted store, compare tenants, resolve human identities, determine current authority, or establish that legal-hold and dependency checks actually ran. Consequently, every receipt reference and boolean embedded in a portable record is **non-authoritative input**.

A protected state transition is admitted only after trusted server bootstrap resolves the referenced receipt from a server-owned `TrustedTransitionReceiptRepository`. The ordinary runtime API does not expose repository or resolver construction. Bootstrap binds an exact per-transition issuer allowlist, and admission binds receipt ID, transition kind, subject, scope, tenant/family, authenticated actor, strict validity interval, revocation state, verification digest, required claims, and operation-specific evidence.

## Mandatory runtime sequence

1. Accept the portable proposal or record into quarantine. Do not persist its requested final state.
2. Extract the receipt reference only as a lookup key.
3. The ordinary `@family/security` package exports no repository, issuer, resolver, or server constructor. Until a sovereign deployment-owned authorization service and dependency boundary are independently reviewed, the resolver seam remains non-exported and test-only. Request handlers, clients, agents, uploads, prompts, connectors, and public fixtures must not supply or instantiate a repository, issuer configuration, resolved receipt, or verified-set object.
4. Reject absent, malformed, future-issued, expired, revoked, wrong-issuer, wrong-digest, mismatched, incomplete, or operation-binding-incomplete receipts. Authorization timestamps require strict timezone-bearing RFC 3339 instants.
5. Resolve and consume the opaque verified receipt exactly once inside the protected operation, using the same authoritative operation timestamp and authorization transaction. Consumption MUST re-query the deployment-owned authoritative repository and revalidate issuer, validity, and current revocation state before admission; a frozen receipt snapshot is not sufficient. Cached, reused, expired, later-revoked, or timestamp-mismatched contexts fail closed. Call `admitTrustedTransition` with that timestamp, the exact transition kind, subject reference, scope reference, actor type, operation-specific binding, and opaque verified receipt set.
6. Persist the final state only when `admitted` is `true`. Otherwise retain the proposal as blocked or pending human review.
7. Write an audit event containing references and decision metadata only, never raw private evidence.

The runtime uses an internal `WeakMap`-bound verified set. Copying receipt fields or constructing an object with the same public shape does not create a verified set.

## Required transition claims

| Transition | Required server-resolved claims | Exact binding | Actor rule |
|---|---|---|---|
| `federation_transfer` | distinct tenants, bilateral human approvals, recipient capability, unexpired scope, recipient receipt | sender and recipient tenants, both approval references, capability, recipient receipt, withdrawal callback | trusted service may finalize after both human approvals |
| `community_activation` | authority identity, appointed human decision maker, human recorder, current review window, bound restrictions | decision, authority, appointed human, recording human, complete restriction set | human only |
| `jurisdiction_activation` | qualified human reviewer, controlling authority, valid authority references, current review window, resolved conflicts | pack ID/version/canonical digest, tenant, applicability, reviewer, authoritative-source references | trusted service evaluates; result still routes to qualified human review |
| `deaccession_authorization` | human authorizer, human actor, retention clearance, legal-hold clearance, dependency closure, suppression plan | artifact, exact recorded human actor, human decision, retention check, legal-hold check, dependency graph, suppression plan | human only |

## Agent action authorization

Agent target scope cannot come from a default, portable boolean, request field, agent manifest, or caller-authored `{ targetScopeVerified: true }` object. Trusted bootstrap resolves an authorization receipt and returns an opaque context bound to family, tenant, authenticated actor, agent, action, exact target resource, target scope, issuer, policy version, strict validity window, and revocation state. `evaluateAgentAction` rejects absent contexts and any mismatched binding before applying the agent manifest allowlist.

## Fail-closed requirements

The runtime returns blocked when:

- the receipt reference is supplied only by the record;
- the trusted repository cannot resolve it;
- the issuer is not an allowlisted trusted service;
- `issued_at`, `verified_at`, or `expires_at` is not a strict timezone-bearing RFC 3339 instant or falls outside the valid current window;
- the receipt is revoked, its verification digest is malformed, or its exact issuer is not allowlisted;
- subject, scope, tenant, transition kind, actor, resource, policy version, payload digest, or operation-specific binding does not match;
- any required claim is missing or false;
- a community activation or deaccession is agent- or service-originated;
- a jurisdiction pack is research-only, expired, superseded, conflicting, unsupported, or lacks a server-resolved receipt.

A successful admission proves only that the transition controls passed. It does not establish historical truth, legal advice, publication permission, identity equivalence, cultural authority beyond the recorded scope, or permission for any later transition.

## Conformance

A runtime is non-conforming if it:

- trusts embedded `true` values;
- accepts a caller-provided list of supposedly verified receipt references;
- permits a client or agent to supply the receipt repository or issuer configuration;
- exposes trusted repository/resolver construction through the ordinary runtime package entry point;
- performs only JSON Schema validation;
- admits an expired or cross-subject receipt;
- allows an agent to activate community authority or authorize deaccession;
- converts jurisdiction admission into autonomous legal authorization.

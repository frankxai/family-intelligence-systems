# Public Artifact Sanitization Protocol v1

Public source code, documentation, fixtures, screenshots, issue bodies, logs, examples, release artifacts, and AI prompts must be synthetic and unlinkable to a real family tenant.

## Automatic block classes

- real names, initials combined with dates/places, contact details, addresses, account IDs, tenant IDs, or family relationships;
- children, dependants, adoption, parentage disputes, genetic information, health, religion, ethnicity, abuse, crime, finances, legal matters, or succession details;
- private or signed URLs, query tokens, bearer values, storage keys, original filenames, device metadata, image EXIF, hidden document properties, logs, analytics payloads, prompts, embeddings, hashes from private artifacts, or screenshots of authenticated surfaces;
- claims that an archive contains or does not contain information about a named person.

## Release gate

1. Generate fixtures from a versioned synthetic-data source.
2. Scan content and media metadata.
3. Review the diff for linkable combinations, not only single fields.
4. Require a human maintainer independent of the contributor for governance, privacy, security, or publication changes.
5. Record the exact commit and sanitization receipt.

A scan pass is necessary but not sufficient. Any ambiguity blocks public release. Security reports use GitHub private vulnerability reporting or another private maintainer-approved channel, never a public issue containing sensitive reproduction data.

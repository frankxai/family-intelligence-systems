# Archival Description Protocol v1

## Purpose

Describe an artifact so that people can find, understand, preserve, and responsibly access it. Description is not authentication, lineage acceptance, publication approval, or a grant of access.

## Required principles

- Use opaque artifact and collection references on private surfaces.
- Preserve original title, language, script, order, and known custody without inventing missing context.
- Record creator/custody uncertainty and description provenance.
- Separate descriptive metadata from claims extracted from the artifact.
- Record rights, sensitivity, access conditions, community restrictions, affected living people, and review state.
- Never place private source URLs, signed URLs, bearer query strings, credentials, real filenames, or identifying metadata in public records.
- A human steward reviews any description proposed for family-wide, federated, or public use.

## Description states

`draft` → `human_review_required` → `private_approved` → optional separate publication workflow.

Agents can create drafts and finding aids. Agents cannot approve authenticity, merge identities, accept lineage, widen scope, or publish.

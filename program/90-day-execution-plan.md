# 90-day execution plan

Status: proposed program sequence

This is a release-gated plan, not authorization to open production, contact relatives, buy domains, send campaigns, or process real family data.

## Phase 1 — Foundation and founding proof (days 1–14)

Deliver:

- claims, evidence, consent, publication, disputes, circles, and succession protocols
- JSON Schemas and policy tests
- English and German public explainers
- German private portal shell, locked in production
- privacy-safe starter download
- Vercel build blueprint and v0 prototype prompt

Exit gate:

- public repositories contain no real family records
- policy tests prove child publication, missing consent, agent authority, and inactivity succession fail closed
- domain and email remain unannounced until verified
- visual QA and accessibility evidence pass on a preview

## Phase 2 — Secure intake and steward review (days 15–35)

Deliver:

- verified domain and mailbox decision
- secure one-time intake links
- malware and file-type quarantine before evidence access
- database-backed case, claim, evidence, consent, and audit persistence
- identity duplicate candidates without automatic merges
- steward queue for accept, dispute, reject, unresolved, and publication review

Exit gate:

- DPIA draft and data map reviewed
- deletion, correction, contest, and export paths tested
- no sensitive attachment is requested through ordinary email
- database row-level security and tenant isolation are independently tested

## Phase 3 — Private family pilot (days 36–60)

Deliver:

- passkey-capable personal accounts and recovery
- invitations and roles for self, household, core circle, extended family, guardianship, and advisors
- source-grounded private family tree and timeline
- German elder-interview workflow with consent and transcript review
- encrypted object storage and complete family export
- GEDCOM 7 projection for accepted, export-eligible claims

Exit gate:

- each participating living adult has their own account and scope
- children use guardian-managed profiles with no public discoverability
- restore drill succeeds from the encrypted export
- no shared household password is treated as production authentication

## Phase 4 — Continuity and repeatability (days 61–90)

Deliver:

- separate emergency, incapacity, and death policies
- continuity guardians, quorum, cooling, revocation, and drill history
- five external founding-family onboarding packets using synthetic demos first
- reviewed skill registry and connector permission manifests
- self-hosted and hosted deployment guides

Exit gate:

- emergency packet reveals only the configured minimum scope
- inactivity and agent inference cannot trigger release
- two-of-three death-release quorum is tested without real release
- every pilot family can export and leave

## Human approvals

Always required for:

- naming/trademark selection and domain purchase
- DNS, production promotion, secrets, and paid services
- public campaign or external message send
- processing real child, genetic, health, legal, financial, or succession data
- accepting disputed lineage, publishing living-person data, or releasing continuity access

## North-star proof

Verified, consented, retrievable family knowledge survives a restore and can be transferred through a human-governed generational transition.

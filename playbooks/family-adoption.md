# Family adoption and activation

The reference runtime is [Family Intelligence OS](https://github.com/frankxai/family-intelligence-os/tree/codex/family-intelligence-2026-10-02). It deploys a premium, zero-data template. Sovereign interfaces are choices above one family-owned archive and authority boundary.

## Sequence and acceptance

1. Deploy the interface. Verify the health route reports locked, no records connected, no remote MCP provisioned. Review Vercel protection separately from family authorization.
2. Name accountable adults: family steward, guardian, technical implementor, recovery trustees. Infrastructure administration alone must not grant archive reads. A host administrator can access server-decrypted data; trustee-held keys and a separate decryption boundary are needed where this threat matters.
3. Provision individual OIDC identities, passkeys/hardware factors, revocable device grants and tested recovery. OAuth authenticates a principal; server-resolved tenant membership, purpose and resource grants authorize each operation. Wallet possession alone cannot establish membership.
4. Provision encrypted originals, derivatives, scoped indexes, audit receipts and isolated backup. Prove an authorized read, a denied cross-member read, revoked-session denial and a clean isolated restore before real intake.
5. Review rights and authority for one synthetic scan. Quarantine, inspect, hash, OCR in an isolated worker, retain page/confidence links, extract candidate claims, review, and index only authorized derivatives. No public Library OS export by default.
6. Connect one chosen AI interface using a separate service identity, read allowlist, bounded budget and approved processor. Test untrusted-document instructions, grant revocation and citations before broadening.
7. Activate one adult-led family review. Workflow definitions propose work; human approval is required for decisions, contact, sharing, publication, claim acceptance and access release. A runtime must enforce limits; a JSON definition is not an executor.
8. Introduce next-generation learning together. Let family members question, revise and choose principles. No loyalty scoring, behavioral surveillance or autonomous child contact.

## Delivery gates

| Gate | Evidence required | Current release |
| --- | --- | --- |
| Template | Build, route and mobile checks; zero private fixtures | Implemented; preview verified separately |
| Archive | Identity, key custody, policy enforcement, audit and restore receipts | Not activated |
| Library processing | Scan isolation, rights review, page provenance and scoped retrieval | Contract only |
| Proactive team | Durable runs, budgets, idempotency, review queue and revocation | Disabled workflow definitions |
| Runtime adapter | Version pin, upstream license/terms review and conformance tests | Profiles/examples only |
| Public release | Independent maintainer review and exact-commit checks | Pull request required |

## Deploy choices

Vercel deploys the template interface. Railway has a standalone Docker configuration, health route and setup guide in the runtime repository; a Railway marketplace template code must be created through its composer before there is a real one-click Railway button. Long-running OCR and AI workers belong in a separately provisioned service, not a request handler.

## Operating rhythm

Weekly: a short private review of proposed actions and disputed/source-less claims. Monthly: grants and devices, processor changes, budgets and dependencies. Quarterly: restore receipt and trustee recovery exercise. These are playbook recommendations, not installed schedules.
